# Software Requirement Specification: Verifiable AI Health Pre-Triage DApp (AegisCare)

## 1. Executive Summary & Vision
The **Verifiable AI Health Pre-Triage DApp** or **AegisCare** serves as an immutable audit registry for AI-generated medical guidance. It addresses critical challenges in digital healthcare including AI liability, hallucination, and data opacity. By integrating the Google Gemini API with the Datagram (BOT Chain) Testnet, every medical pre-triage assessment generated by the AI is cryptographically signed and stored permanently on-chain.

* **Primary Goal:** Provide an accessible, pastel-themed Web3 interface featuring distinct **User** and **Admin** entry points.
* **Key Proposition:** Ensures AI-generated healthcare advice cannot be silently altered, deleted, or denied by the AI provider or health operator.

---

## 2. Access & Routing Architecture

To separate public patient interactions from administrative oversight and audit, the DApp implements two main route views using `react-router-dom`:

```
                    ┌─────────────────────────┐
                    │     App Entry Point     │
                    └────────────┬────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
       [ User Portal Link ]            [ Admin Portal Link ]
      Route: / (Public)               Route: /admin (Restricted)
                 │                               │
       - Input Symptoms                - Complete Audit Logs
       - Request AI Assessment         - Analytics & Filters
       - Auto-Commit to Blockchain     - Contract Verification
```

### Route Specifications
1. **User Portal (`/`):** Dedicated to patients for entering symptom profiles, triggering AI pre-triage requests, and submitting assessments directly to the smart contract.
2. **Admin Portal (`/admin`):** Dedicated to compliance officers, healthcare supervisors, and system admins. Provides deep inspection tools, log filtering, system health checks, and global audit history.

## 3. Technical Stack & Dependencies

### Core Technologies
* **Frontend Framework:** React.js (Vite / Next.js SPA) with Tailwind CSS for component-based UI styling.
* **Navigation & Routing:** React Router DOM (v6) for multi-view client-side navigation.
* **State Management:** React Context API or custom hooks (`useWeb3`, `useGemini`) for global wallet and provider states.
* **AI Engine:** Google Gemini REST API (`gemini-2.5-flash` endpoint).
* **Blockchain Network:** Datagram / BOT Chain Testnet
  * **Chain ID:** `968`
  * **RPC URL:** `https://rpc.bohr.life`
  * **Explorer:** `https://scan.bohr.life`
  * **Native Gas Token:** `DGRAM` / `BOT`
* **Smart Contract:** `AIAdvisor.sol`
  * **Deployed Address:** `0x3AfD2a35656733ea7369f30ad5989cab4b2d9bd9`
  * **EVM Compatibility:** Solidity `0.8.19` (Target: `paris`/`london`)
* **Web3 Library:** Ethers.js (v5) installed via npm (`ethers`).
* **Wallet Connector:** MetaMask Injected Web3 Provider (`window.ethereum`).

## 5. Key Functional Features & View Specifications

### View 1: User Portal (`/`)
1. **Wallet Connector Component:** Shows connection status in a soft green pastel badge when active with truncated address (`0x3AfD...9bd9`).
2. **Symptom Input Field:** Soft bordered multi-line text entry for entering health symptoms.
3. **Execution Trigger:** Pastel blue CTA button (**Generate & Log to Chain**).
4. **Automated AI Pre-Triage Execution Flow:**
   * **Step 1:** Queries Gemini API (`gemini-2.5-flash`) asynchronously enforcing a 3-part structured assessment (Risk Level, Recommended Next Action, Medical Disclaimer).
   * **Step 2:** Previews generated assessment in UI output panel.
   * **Step 3:** Immediately opens MetaMask signature prompt to write payload to `AIAdvisor.sol` with explicit gas limit override (`{ gasLimit: 3000000 }`).

### View 2: Admin Portal (`/admin`)
1. **Metrics Summary Dashboard:**
   * Total Audited Logs (`getAdviceCount()`).
   * Active Network Chain ID (`968`).
   * Smart Contract Address & Explorer Verification Link.
2. **Global Audit Log Feed:**
   * Queries `getAdviceCount()` and iterates reverse-chronologically through `adviceLogs(i)`.
   * Renders log cards showing Patient Wallet, Unix Block Timestamp, User Symptom Prompt, and On-Chain AI Advice.
3. **Filtering & Refetch Control:**
   * Manual RPC refetch button to update records without page reload.
   * Address search bar to filter logs by specific patient wallet address.
